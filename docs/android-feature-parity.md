# Android 功能对等清单

本文档是 Android 迁移的验收账本。功能基线冻结在 `c3c8326`；每项状态只能取 `planned`、`in_progress`、`blocked` 或 `verified`。`verified` 必须同时具备自动化测试或真机验收证据，不能只以“界面已出现”判定。

## 验收规则

- Android 行为、安全边界和失败恢复必须与 iOS 基线一致；平台专属交互按 Material 3 重做。
- 共享协议 fixture 必须由 Go、Swift、Kotlin 同时消费；协议漂移直接使 CI 失败。
- 破坏性操作、凭据切换、HTTP 传输和文件访问采用 fail-closed。
- 手机、平板、折叠屏和窗口缩放共用同一状态源，切换布局不能丢失会话、草稿或审批。
- `verified` 的证据写入“验收证据”列；测试编号以 `A-` 开头，真机场景以 `D-` 开头。

## 后台能力声明

Android 首版不使用云推送或常驻前台服务。完成、失败和审批通知只在应用进程仍存活且拥有活动会话时保证送达；进程被系统终止后不承诺离线通知。此边界必须在产品说明和测试用例中明确，不能以 WorkManager 轮询伪装实时推送。
